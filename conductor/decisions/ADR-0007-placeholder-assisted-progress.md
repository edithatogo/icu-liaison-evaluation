# ADR-0007 — Placeholder-assisted development and strict evidence gates

**Status:** accepted for portable synthetic source work, 18 November 2026.

## Decision

Proceed with P3–P6 pipeline integration using versioned, source-labelled
synthetic fixtures and explicit null placeholders where site data or permission
is missing. Every placeholder is linked to an existing JSON field, a prospective
owner, an acceptance checklist and gates it blocks. Never promote a placeholder
by self-declaration or by a matching SHA-256; evidence admissibility requires
separate independent clinical, data-governance, scientific and Finance review.

## Dependencies and constraints

Retain the existing P4 engine and P5 reports. Use P3's controlled synthetic-data
intake, SciPy holdout comparisons and P6's validated event trace. The native
P6 consumer **must** use the pinned Kairos staged resource runtime; do not write
another scheduler. Dapane and Voiage actual native execution, the publisher's
2024/25 CCR document, dedicated repository CI and local CHHHS authorisations
remain unresolved. The annual P4 placeholder cohort is not derived from the
few fictional P3 input rows. No P7 code returns investment readiness.

## Consequences

The programme can create deterministic cross-track source output while
isolating all real replacements to private and reviewed lanes. The public
source builds remain useful without accidental claims of real site effect,
savings or independently qualified native simulation.
